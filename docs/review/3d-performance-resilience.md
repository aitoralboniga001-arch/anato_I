# All-model performance and GPU resilience audit — 2026-10-17

Scope: every `Stage3D` view: diaphragm (topic 7), calvaria and limb rotation (topic 8), domains (topic 9), and nine heart views (topic 10). Topics 1–6 and 11 currently have no `Stage3D` models. Work performed directly, without subagents.

## Findings and changes

1. **Unchanged React frames still requested GPU draws.** The renderer now compares visible frame values, immutable mesh/stream identities, transforms, highlights, clipping and lighting. It coalesces pending frames and uploads at drawing time. Unchanged pictures sleep; changed highlights, camera moves, resize and blood phase still wake it.
2. **Moving models consumed up to one draw and pose calculation per display frame.** GPU drawing per renderer and timeline pose publishing now have a 30 Hz ceiling, including on 120 Hz screens. The separate class/manual-step glide loop uses the same ceiling. The simulator uses elapsed time between accepted updates, preserving stage duration and manual seek coordinates. This deliberately trades 60 Hz model motion for lower sustained CPU/GPU work. Camera input stays responsive, with GPU presentation capped at 30 Hz. Other UI state updates can still cause React renders; this is not a claim that every component renders at most 30 times per second.
3. **A final pixel cap did not bound intermediate allocations.** Three's `setPixelRatio` resizes the previous logical dimensions before `setSize`. The new resize path shrinks to 1×1, then sets size and ratio together. It caps both intermediate and final buffers at **2,000,000 pixels**, and respects texture/renderbuffer dimension limits. Small views retain DPR 2; large views are somewhat softer. The former cap was 3.2M pixels.
4. **2D pages created contexts and prebuilt unused geometry.** Removed viewport context prewarming and whole-topic geometry prewarming. A 3D view requests its own geometry only when mounted. Its worker terminates once the pending batch arrives, releasing duplicate worker meshes, SDF fields and module caches. Main-thread geometry remains cached for revisits.
5. **Parked contexts retained full buffers and meshes for 60 seconds.** After the 180 ms handover interval they now release model geometry/materials and shrink the drawing buffer to 1×1. The remaining context is disposed after 5 seconds. A detached viewport is disposed immediately. Host metadata uses weak maps rather than retaining detached DOM nodes.
6. **Hidden/offscreen work had no explicit renderer gate.** Page visibility and viewport intersection suspend the drawing loop. The playback clock suspends while the document is hidden and resumes without counting hidden time as a huge frame. CSS-hidden scene groups skip drawing. A context is not created for an initially hidden document.
7. **Failure protection ended on reload.** Context loss, rejected context creation and asynchronous compile rejection trip a session-storage circuit. The same tab keeps the flat SVG fallback across view switches and reloads. Storage denial retains in-memory protection. Renderer creation uses the browser's default power choice and rejects major performance caveats; these are browser hints/constraints, not a driver repair.
8. **A GPU upload could corrupt a cached CPU pose.** Geometry attributes referenced old immutable mesh arrays, and `.set(nextPose)` wrote into those arrays. Updates now swap attribute references, including UV and index data; they never overwrite an earlier mesh-cache entry. Unused bounding-sphere scans were removed because these meshes disable frustum culling.
9. **Reading holds kept publishing identical scene positions.** Duplicate position updates are suppressed, including narrated observation holds.
10. **An unrelated automatic index warm caused startup spikes.** A production CPU profile captured Kimu text folding during the four-second automatic warm. Search now warms on launcher hover/focus/open. This is a one-off startup saving, not evidence of per-frame tokenization.

No mesh-resolution reductions, new graphics passes or runtime dependencies were added. Existing procedural anatomy, labels, manual controls and flat fallback remain in place.

## Evidence and reproducibility

- Baseline: commit `5b97561`, production server port 3120; `docs/perf/renderer-audit-before/results.json`. Three representative views were profiled sequentially on the Radeon 780M through ANGLE D3D11.
- Full after survey: `scripts/perf-3d-polish.mjs`, all 13 views, 1536×960 CSS, DPR 2, stage time 0.55, held and eight-wheel close-ups. The bounded GPU metric includes CPU submission and completion readback; it is not a hardware GPU timer.
- Lifecycle assertions: `scripts/check-3d-resilience.mjs`. Instruments worker lifecycle and **every** canvas width/height assignment, checks 2D contexts, final/transient allocations, held sleep, real viewport intersection, synthetic document-visibility events, parking/disposal, reopening, actual `WEBGL_lose_context`, context refusal, and fallback across reloads. The synthetic visibility check is not a claim of a physical tab-switch test.
- Playback/control assertions: `scripts/check-3d-playback.mjs`. Reads the real timeline's position to check elapsed-time playback, hidden pause/resume, manual reading holds, camera wake/settle and immediate disposal of a detached viewport on SPA navigation. It starts topic 10's actual class UI and observes its separate glide loop, using the supported subtitle/timer fallback rather than audible speech in the diagnostic browser.
- Pure regression tests cover frame equivalence and visible changes, 120 Hz input / 30 Hz output, suspend/resume, storage failure, worker termination/error recovery, and forward/backward mesh ownership.

Measurements and completed validation are recorded in Batch 7 of `docs/perf/README.md`.

## Remaining work and limits

- Domains still has many translucent draws and about 556k drawn triangles. A carefully measured material/draw batching experiment is preferable to further coarsening landmarks. It must preserve transparent order, clipping, structure picking and teaching colours.
- Rapidly deforming heart/vein poses still construct new procedural geometry. Persistent deformable buffers could reduce allocation further, but need matching hit geometry and deterministic forward/backward seeking. The 30 Hz pose cap reduces the current work without changing that anatomy system.
- Main-thread static geometry slots stay cached after first use; only the worker's duplicates are released. The dynamic mesh cache already has a 24 MiB budget. No claim is made that all application memory is capped at that size.
- Pixel and draw limits apply per renderer. View transitions can briefly overlap outgoing and incoming views; the limits are not a budget for every tab or program on the computer.
- The existing Windows event establishes **bugcheck 0x133 (DPC watchdog timeout)**. It does not identify the responsible driver; no useful crash dump was recorded. See [Microsoft's diagnostic guidance](https://learn.microsoft.com/en-us/windows-hardware/drivers/debugger/bug-check-0x133-dpc-watchdog-violation). Reduced workload and WebGL fallback mitigate application load and recoverable context failure. JavaScript cannot guarantee prevention of an OS/driver crash that occurs before the browser can receive an event.
- No driver, registry, OS recovery or browser GPU-blocklist setting was changed. A supported Lenovo/AMD driver check and a crash dump, if another watchdog occurs, remain the route to identifying a system-level cause.
